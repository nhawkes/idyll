# Hydration node-matching: prior art survey & recommendation for idyll

*Research date: 2026-07-05. Question: how should idyll's client "claim" server-rendered DOM — keep the markerless positional walk and harden it, emit minimal markers, or macro-normalize markup shapes?*

idyll's two known holes in the positional tandem-walk:

1. **Text merging** — adjacent static+dynamic text serializes as one string; the browser parses it into ONE text node, but the client template has separate nodes (`<idyll-t>` wrappers exist only in templates, not SSR HTML).
2. **Region ends** — a control-flow region (list/conditional) must currently be the *last* dynamic child of its parent because the walk can't tell where the expanded rows end and the following siblings begin.

Every framework surveyed hits exactly these two problems. The solutions cluster into three families: **comment markers** (React/Svelte/Vue/Solid/Leptos-partially/Qwik1/Marko), **positional walking with known structure** (Leptos 0.7, Marko's encoded walks), and **compile-time normalization** (Svelte 5's single-text-node compilation — the quiet third answer nobody frames as one).

## Per-framework notes

### React 18/19

**Artifacts.** `renderToString`/`renderToPipeableStream` emit exactly two kinds of markers: a `<!-- -->` comment between adjacent text segments, and Suspense boundary comments — `<!--$-->` (complete), `<!--$?-->` (pending, streaming), `<!--$!-->` (client-render fallback), `<!--/$-->` (close). No attributes, no per-element ids (post-React-16, `data-reactid` is long gone; `data-reactroot` also gone in 18).

**Text.** The separator exists precisely because "the DOM created by the initial HTML has only 1 text node 'Count: 0', but the [expected] DOM has 2 text nodes" — a comment node "nicely separates the boundary of the 2 text nodes" ([Tan Li Hau's writeup](https://dev.to/tanhauhau/hydrating-text-content-from-server-side-rendering-29n1)). The hydration walker (`getNextHydratable`) *skips* comment nodes when matching elements/text — the comment's only job is to have prevented the parser from merging. Negative control: `renderToStaticMarkup` omits separators and React explicitly warns hydrating its output ([react#11596](https://github.com/facebook/react/issues/11596)).

**Lists/conditionals.** Purely positional — the fiber tree walks first-child/next-sibling and claims (`tryToClaimNextHydratableInstance`). React does not mark where a list ends; it doesn't need to, because the client re-renders the full tree and therefore knows exactly how many children each fiber produced. This is the key insight for idyll: **positional works when the claimer knows the full expected structure**. Suspense is the exception because streaming replaces content out-of-order and selective hydration must find boundaries *before* rendering children — hence real markers ([jser.dev deep dive](https://jser.dev/react/2023/03/27/hydration-with-suspense/)).

**Mismatch.** Dev warning; in 18/19 a mismatch throws a recoverable error and the root (or nearest Suspense boundary) is **re-rendered client-side**, discarding server DOM. React 19 stopped trying to patch individual mismatches and instead logs one diff. Docs: "treat mismatches as bugs"; explicitly lists *extra whitespace around the root HTML* as a common cause ([hydrateRoot docs](https://react.dev/reference/react-dom/client/hydrateRoot), [Next.js hydration-error page](https://nextjs.org/docs/messages/react-hydration-error)).

**Battle scars.** Cloudflare Auto-Minify stripping React's comment markers crashed isomorphic apps ([react#10778](https://github.com/facebook/react/issues/10778)) and later broke React 18 streaming/Suspense hydration the same way ([Cloudflare community](https://community.cloudflare.com/t/auto-minify-html-and-react-hydrate/528537), [ryanmr writeup](https://www.ryanmr.com/posts/cloudflare-minified-next) — whitespace minification broke it too). Cloudflare deprecated Auto Minify in 2024, partly over this class of breakage.

### Svelte 5

**Artifacts.** Server emits `BLOCK_OPEN` = `<!--[-->`, `BLOCK_CLOSE` = `<!--]-->`, `BLOCK_OPEN_ELSE` = `<!--[!-->` (tells the client the *else* branch was SSR'd so it doesn't try to claim the if-branch's shape), `EMPTY_COMMENT` = `<!---->` ([internal/server/hydration.js](https://github.com/sveltejs/svelte/blob/main/packages/svelte/src/internal/server/hydration.js)). Every component instance, `{#if}`, `{#each}`, `{#await}`, `{@html}` region is wrapped. Svelte 3/4 hydration had no markers and was notoriously approximate (it "repaired" by moving nodes); the 5.0 rewrite chose explicit boundaries so claiming is exact and `{@html}` / `{#each}` ends are findable.

**Text — the interesting part.** Svelte 5 does NOT emit text separators. Instead the compiler **merges every contiguous run of static text + expressions into one text node**: the client template contains a single `" "` placeholder and one effect does `set_text(node, \`Count: ${count}\`)` — "just the same as `text.nodeValue = ...`" ([Compile Svelte 5 in your head](https://lihautan.com/compile-svelte-5-in-your-head)). The client's expected shape is *defined* to match what the parser produces. This is macro-normalization done in the compiler, and it costs them fine-grained text updates (the whole run is rewritten on any change) — a cost Svelte accepts, but a fine-grained-signals framework (Solid, and idyll) may not want.

**Mismatch.** `w.hydration_mismatch(); throw HYDRATION_ERROR;` → caught in `hydrate()`, which (unless `recover: false`) clears the target and re-mounts fully client-side ([internal/client/render.js](https://github.com/sveltejs/svelte/blob/main/packages/svelte/src/internal/client/render.js)).

**Cost complaints.** Users report marker bloat — one CMS-embedded project blew a hard HTML-size limit ([#15200](https://github.com/sveltejs/svelte/issues/15200)); measured overhead in [#14099](https://github.com/sveltejs/svelte/issues/14099) was 2.3KB→2.8KB raw but only 1.8→1.9KB gzipped. Maintainers keep them because SSR output must be claimable without knowing which components will hydrate. They special-cased the `<pre>` leading-newline parser quirk in the claim walk ([PR #14783](https://github.com/sveltejs/svelte/pull/14783)).

### SolidJS / SolidStart

**Artifacts.** `data-hk="…"` hydration-key attributes (hierarchical path ids, base-36, emitted by `ssrHydrationKey()`), `<!--!$-->` comment separators between adjacent dynamic text parts (emitted by `resolveSSRNode` in [dom-expressions server.js](https://github.com/ryansolid/dom-expressions/blob/main/packages/dom-expressions/src/server.js)), plus `<template id="pl-N">`/`<!--pl-N-->` placeholder pairs for streamed Suspense content, and the `hydrationScript` (event-capture shim + streaming glue).

**Matching.** Hybrid: keys locate hydration *roots* (so out-of-order streamed chunks can attach), then `getNextElement()` walks positionally inside a root, `getNextMarker()` consumes the text separators. Keys exist because Solid streams and resolves async out of order — order-independence is the feature bought with an attribute on essentially every element.

**Mismatch.** Throws "Hydration Mismatch" and stops; no recovery path ([docs](https://docs.solidjs.com/reference/rendering/hydrate)). Community guidance is simply "don't mismatch".

### Qwik

**Artifacts (v1).** The maximal-serialization end of the spectrum: `q:container` on the root, `<!--qv q:id=7 q:key=…-->` … `<!---->` comments materializing *virtual* (fragment) nodes, `q:id` attributes cross-referencing elements from the state blob, `<!--t=8-->123<!---->` wrapping each dynamic text node, `on:click="chunk.js#handler[0]"` QRL attributes, and `<script type="qwik/json">` with the serialized reactive graph ([resumable docs](https://qwik.dev/docs/concepts/resumable/)). Granularity: enough that the client **never re-runs the app** — the DOM plus the JSON *is* the resumed heap.

**v2 correction.** The [Qwik 2.0 post](https://qwik.dev/blog/qwik-2-coming-soon/) admits component-boundary comments were "a nontrivial amount of additional HTML text", made worse by streaming ("just-in-case" emission), and moves all vnode data into a single `<script type="qwik/vnode">` at the end of the document that references DOM nodes **by deterministic position** — i.e., even the resumability camp converged on *positional reference driven by out-of-band data* over inline markers.

### Leptos (closest prior art)

**History.** 0.1–0.6 gave every element a unique hydration ID and found nodes by ID. 0.7 (tachys rewrite) deleted the ids and **walks the DOM positionally with a cursor**, in tandem with the typed view tree — near-identical to idyll's tandem walk. Stated reasoning ([Hydration Bugs chapter](https://book.leptos.dev/ssr/24_hydration_bugs.html)): "much better performance characteristics (shorter, cleaner HTML output and faster hydration times)" but "less resilient to the invalid or edge-case HTML examples" (`<tbody>` auto-insertion, `<p>` auto-closing); on net "fixes a number of other edge cases and bugs… more resilient on net."

**But it is not markerless.** tachys emits a **3-byte bogus comment `<!>`** (parses to an empty comment node) in exactly the two places idyll has holes:

- *Text runs* — [`view/strings.rs`](https://github.com/leptos-rs/leptos/blob/main/tachys/src/view/strings.rs): `if matches!(position, Position::NextChildAfterText) { buf.push_str("<!>") }` — a separator is emitted **only** when the previous sibling was also text. Empty strings render as a single space so a text node always exists to claim (no splitText anywhere).
- *Region ends* — [`view/iterators.rs`](https://github.com/leptos-rs/leptos/blob/main/tachys/src/view/iterators.rs): after all items of a `Vec` view, `buf.push_str("<!>")`; hydration does `cursor.next_placeholder(position)` and keeps that comment node as the region's **anchor** (`VecState { states, marker }`) — it doubles as the insertion anchor for later list mutations, which a positional walk alone can never give you. Compile-time-sized arrays `[T; N]` emit nothing.
- *Branches* — optional `mark_branches` mode wraps conditional branches in `<!--bo-…-->`/`<!--bc-…-->` ([`view/either.rs`](https://github.com/leptos-rs/leptos/blob/main/tachys/src/view/either.rs)), needed mainly so streaming Suspense fallback→content swaps can find their extent; off by default.

**Mismatch.** Panics ("could not convert current node into marker node", [#2917](https://github.com/leptos-rs/leptos/issues/2917)); no recovery. Leptos accepts documented parser traps as user responsibility.

### Vue 3 (brief)

Positional vnode↔DOM walk (`hydrateNode` returns the next DOM node to the parent's loop). Comments only where structure is invisible in the HTML: `<!--[-->`/`<!--]-->` around fragments (multi-root components, `v-for` output), `<!---->` as `v-if:false` placeholder, teleport anchors; `locateClosingAnchor` scans forward with a nesting counter to find fragment ends. Text: no separators — Vue *knows* browsers merge adjacent text vnodes and `hydrateChildren` just compares/patches the merged content. Mismatch: classified warnings, then patch or clear-and-remount subtree; `data-allow-mismatch` opt-out. The most tolerant of the group ([DeepWiki: vuejs/core hydration](https://deepwiki.com/vuejs/core/7.2-hydration), [Nuxt mismatch field guide](https://harlanzw.com/blog/nuxt3-hydration-node-mismatch)).

### Marko (brief)

Marko 5/6 (resumable) emit component-boundary comment markers (v6: key on the opening marker only, closing markers are stack-matched) plus a script payload containing state and **encoded walks** — literal "series of `firstChild && nextSibling`" instructions telling the client how to step from a marker to each dynamic node ([why-is-marko-fast](https://markojs.com/docs/why-is-marko-fast/), [release notes](https://github.com/marko-js/marko/releases)). I.e., the server, which knows the exact emitted structure, ships *navigation instructions* rather than making the client search. Conceptually this is "positional walk driven by out-of-band exact knowledge" — the same shape as idyll's command stream.

## HTML-parser normalization traps (documented cases)

These are the only ways idyll's SSR HTML can differ from the serialized stream — the browser rewrites markup *before* any framework code runs. All are documented framework bugs, not hypotheticals:

| Trap | What the parser does | Documented case |
|---|---|---|
| **Adjacent text merging** | Two logical text nodes serialize adjacently → parse to ONE text node | The founding problem: React `<!-- -->` separators ([tanhauhau](https://dev.to/tanhauhau/hydrating-text-content-from-server-side-rendering-29n1)); Solid `<!--!$-->`; Leptos `<!>` |
| **Empty text vanishing** | `""` between elements produces no text node at all | Leptos renders `" "` for empty strings (strings.rs) |
| **`<table>` foster-parenting / `<tbody>` insertion** | Text/invalid children hoisted out of table; `<tbody>` auto-inserted around `<tr>` | [next.js#36754](https://github.com/vercel/next.js/discussions/36754), [react#24519](https://github.com/facebook/react/issues/24519), Leptos book |
| **`<p>` auto-closing** | Block element inside `<p>` closes it; stray `</p>` becomes a new empty `<p>` | [Next.js hydration-error docs](https://nextjs.org/docs/messages/react-hydration-error), Leptos book; React's `validateDOMNesting` exists solely to warn about this class |
| **`<pre>`/`<textarea>` leading newline** | Parser drops a single newline immediately after the open tag | [svelte PR #14783](https://github.com/sveltejs/svelte/pull/14783) — `firstChild` of `<pre>` skipped the expected text node entirely |
| **Comment stripping by middleboxes** | CDN/minifier removes comments the framework depends on | Cloudflare Auto-Minify vs React ([react#10778](https://github.com/facebook/react/issues/10778), [community thread](https://community.cloudflare.com/t/auto-minify-html-and-react-hydrate/528537)); whitespace minification broke Next streaming ([ryanmr](https://www.ryanmr.com/posts/cloudflare-minified-next)); same class breaks Vue fragment anchors |
| **Whitespace around root / between tags** | Not collapsed by the parser itself, but template-side pretty-printing or middlebox minification changes text nodes | react.dev lists "extra whitespace around the React-generated HTML" as a top hydration-error cause |
| Others (rare) | `<select>` discards non-option children; `<html>/<head>/<body>` implied-tag shuffling; duplicate `<tbody>`; SVG/foreignObject case-folding | Scattered across the same trackers |

Note what is NOT on the list: the parser does **not** collapse whitespace inside normal text, does not strip comments, does not reorder attributes. The DOM is a faithful parse of the bytes *except* for the tree-construction rules above — all of which are knowable at macro time from the tag names alone.

## Recommendation for idyll

idyll has a property none of these frameworks have: **the SSR HTML is by-construction the exact serialization of the command stream the client replays.** React/Svelte/Vue must defend against *app logic* diverging (Date.now(), window checks, locale) — that's what mismatch-recovery machinery is for. For idyll, divergence can only come from the parser's tree-construction rules. That changes the trade-off completely: markers in the other frameworks are mostly *insurance against unknowable client shape*; idyll's client shape is knowable to the byte.

### Evaluating the four options

**(i) Minimal markers where the walk is ambiguous** — the Leptos 0.7 design, precisely: `<!>` (3 bytes, bogus-comment → empty comment node) after a text node when the next sibling is also text, and one `<!>` after each control-flow region. React's equivalents are `<!-- -->` and (for the only region kind it streams) `<!--$-->…<!--/$-->`. Proven, cheap, and the region-end comment does double duty as the *live insertion anchor* the list needs after hydration anyway (Leptos stores it in `VecState.marker`). Costs: no longer clean HTML; inherits the middlebox-stripping fragility that actually bit React/Vue in production; and it papers over information idyll already possesses.

**(ii) Full Svelte-style region markers** — wrap every component/if/each in `<!--[-->…<!--]-->`. Buys robustness idyll doesn't need (Svelte needs it because the claimer doesn't know what was SSR'd — idyll's claimer knows *exactly*), and brings the size/mess complaints (#14099/#15200) and marker-stripping fragility. **Rejected** — this is insurance against a failure mode idyll cannot have.

**(iii) Markerless + macro-normalize (wrap dynamic text in an element)** — Svelte 5 shows the *merge* flavor works: compile contiguous text runs into one node, update wholesale. But idyll's `<idyll-t>` flavor — wrapping dynamic text in a real element in the *served* HTML — is the one nobody shipped: it changes CSS (`p > span` selectors, `::first-line`, whitespace between inline elements), inflates output more than a comment would, and breaks the "clean HTML" goal worse than markers do. React considered and rejected `<span>` wrappers for text back in the `data-reactid` era for exactly the CSS/semantics reasons. The Svelte merge flavor also sacrifices fine-grained text patching, which a signals framework shouldn't.

**(iv) Markerless + splitText using known lengths from the command stream** — no framework does this *because none of them can*: their SSR output is not a deterministic serialization of data the client independently holds. Vue comes closest (compares merged text and patches); Marko's encoded walks are the same philosophy (server-side exact knowledge shipped as navigation instructions, not searchable markers). idyll can: the command stream carries every text node's exact content, so the claimer can `splitText(offset)` a merged DOM node into the template's shape deterministically, and *synthesize* an empty text node when the stream says one exists but the parser produced none.

### Recommended design: (iv) as the core, with (i)'s region anchor — created, not parsed

**1. Fix text merging with stream-driven `splitText` — stay markerless.** The claim walk should be driven by the command stream (which knows each text node's exact bytes), not by naive template-node identity. When the walk expects text of length *L* and the DOM text node is longer, `splitText(L)` and continue claiming inside the remainder; when it expects text and finds none (empty dynamic string, or region rendered zero nodes between two texts), insert the empty text node. This is exact, costs zero bytes on the wire, is immune to comment-stripping middleboxes, and preserves fine-grained per-node text patching. One caveat to document: HTML-escaping means *serialized* length ≠ text-node length — split on decoded character counts, which the client has because it has the actual strings.

**2. Fix region ends by counting, not marking.** The "region must be last" restriction exists because the walk consults only the template. But the seed/command stream necessarily records how many instantiations each control-flow region produced and each instantiation's root-node count — otherwise the client couldn't replay. Drive the walk from that: claim exactly *rows × per-row roots* nodes, recursively. A conditional that produced nothing consumes zero nodes (and its surrounding texts, now merged, are handled by rule 1). Where a live anchor node is needed for post-hydration list mutations (Leptos keeps its `<!>` for this), **create a fresh empty text node or comment at claim time and insert it** — an anchor the client makes is exactly as good as one the server shipped, and it never appears in the HTML.

**3. Macro-normalize for the parser's tree-construction rules — "emit the parse tree, not the source text."** All the real-world traps are static properties of tag names: auto-insert `<tbody>` in the template/SSR output so server and parser agree; reject (compile error) block-in-`<p>` and other `validateDOMNesting`-class nestings; emit the doubled leading newline for `<pre>`/`<textarea>` content that starts with one (or strip it on both sides). This is parse-don't-validate applied to serialization: make the serialized form a fixed point of the browser parser. Leptos documents these traps and shrugs; idyll's macro sees the tags and can close them by construction.

**4. Mismatch policy: assert, loudly.** Because divergence proves a bug in idyll (or a middlebox rewriting the body), do what Solid/Leptos do — fail hard in dev with the expected-vs-found node — plus a production escape hatch that abandons claiming and lets the client rebuild from the stream it already holds (idyll's replay stream makes Svelte-style clear-and-remount nearly free, and unlike Svelte it's guaranteed to produce identical UI).

**Fallback trigger.** If idyll later adds **out-of-order streaming SSR** (React `<!--$?-->`, Solid `pl-` placeholders) the calculus changes: content that arrives after the walk started genuinely needs discoverable boundaries, and that is the moment to add Leptos-style `<!>`/`<!--$-->` markers — for those regions only. Until then, markers would encode information the client already has.

**One-line version:** idyll should keep clean markerless HTML and harden the walk with what makes it unique — drive claiming from the command stream (splitText by known decoded lengths; consume regions by known row counts; synthesize anchors client-side), and macro-normalize templates to be fixed points of the HTML parser; adopt minimal `<!>` markers only if/when out-of-order streaming arrives.
